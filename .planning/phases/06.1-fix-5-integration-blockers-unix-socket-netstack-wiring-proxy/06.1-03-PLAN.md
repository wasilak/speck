<objective>
Fix Bug 4: the `start()` handler creates and starts a containerd task but never reads the `speck.port_bindings` label stored during `create()`. Published ports are silently non-functional.

Purpose: `create()` stores port bindings in the containerd container label `speck.port_bindings` as a JSON-serialized `HashMap<String, Vec<PortBindingBody>>`. The `start()` handler has access to the container info (it already calls `client.container_get(&id)`) but discards the labels without acting on them. After this fix, `start()` reads the label, parses the JSON, and calls `state.guest.add_port_map(host_port, container_port)` for each binding. The port map routes through VmThread to SpeckNet's PortPublishBridge (which is live after Plan 06.1-02 fixes).

Output: Modified `start()` handler in `containers.rs` that, after `task_start`, reads `info.labels.get("speck.port_bindings")`, deserializes with `serde_json::from_str`, and calls `state.guest.add_port_map()` per binding.
</objective>

    Modify the `start()` async handler in containers.rs. Insert port map application between `client.task_start(&id).await?;` and the `emit_event` call.

    The insertion block:
    - Check if `info.labels` (already retrieved via `client.container_get(&id)`) contains the key `"speck.port_bindings"`.
    - If present, attempt `serde_json::from_str::<HashMap<String, Vec<PortBindingBody>>>(pb_json)`. On deserialization error, log `tracing::warn!(label = pb_json, "failed to deserialize speck.port_bindings; skipping port maps")` and continue without returning an error (malformed label should not fail the start operation).
    - If deserialization succeeds, iterate over the map: for each `(port_proto, host_bindings)` entry:
      - Split `port_proto` on `/` and take the first segment; parse as `u16` for `container_port`. Skip the entry if parse fails with `tracing::warn!(port_proto = port_proto, "invalid container port in speck.port_bindings; skipping")`.
      - For each `PortBindingBody` in `host_bindings`: if `hb.host_port` is `Some(hp_str)` and `hp_str.parse::<u16>()` succeeds as `hp`, call `state.guest.add_port_map(hp, cp)`.     - If `host_port` parse fails (non-numeric or out of u16 range), log `tracing::warn!` and skip that binding.

    The `HashMap` import is already present at the top of containers.rs. `PortBindingBody` is already defined in this file. `serde_json` is already a dependency. No new imports are needed.

    Do NOT modify the `create()`, `stop()`, `inspect()`, or `list()` handlers. Do NOT add new error variants. Do NOT change the HTTP response of `start()` — it remains `Ok(StatusCode::NO_CONTENT)`.

    Security: `parse::<u16>()` naturally rejects values > 65535. Privileged ports (≤ 1024) are not rejected here — that validation already exists in `GuestConfig::validate()` which runs at VM start. For dynamic port maps added at runtime, if a port ≤ 1024 is requested, `add_port_map` may silently succeed or fail at the netstack level; log the warning and continue.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.1-06 | Tampering | Malformed speck.port_bindings JSON label | mitigate | `serde_json::from_str` returns `Err` on malformed JSON; handler logs warning and skips — no panic, no 500 response |
| T-06.1-07 | Tampering | Out-of-range host/container port in label | mitigate | `parse::<u16>()` naturally rejects values > 65535 (parse error → warn + skip); container_port == 0 is skipped by the same parse path since valid u16 range 0..=65535 is accepted but PortPublishBridge will reject port 0 at bind time |
| T-06.1-08 | Elevation | Guest.add_port_map with privileged host port ≤ 1024 | accept | macOS requires root to bind ports ≤ 1024; the TcpListener::bind in PortPublishBridge will return EACCES at runtime; warn is logged at that point |
</threat_model>
