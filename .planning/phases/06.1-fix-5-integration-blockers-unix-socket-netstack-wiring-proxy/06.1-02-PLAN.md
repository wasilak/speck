<objective>
Fix Bug 3 (speck_home not created and not passed to GuestConfig) and the up.rs portion of Bug 2 (netstack not wired — GuestConfig missing network config, SpeckNet never spawned, port_map_channel never set).

Purpose: The `run_up` function in up.rs builds a GuestConfig without `.network()`, never calls `create_dir_all` for speck_home, and never spawns SpeckNet. Consequences: (a) VZFileHandleNetworkDeviceAttachment is not attached — guest has no network; (b) SpeckDockerd's UnixListener::bind fails on first run if speck_home doesn't exist; (c) GuestConfig.speck_home defaults to $HOME/.local/share/speck even when $SPECK_HOME is set, causing VirtioFS to share the wrong directory.

Output: Modified `crates/speck-cli/src/commands/up.rs` with: `create_dir_all(speck_home)` at the top; `.speck_home(speck_home)`, `.network(NetworkConfig::default())`, `.dns_vsock_port(53)` added to the GuestConfig builder; after `guest.wait_for_ready()`: create tokio mpsc port_map channel, call `guest.set_port_map_channel(port_map_tx)`, call `guest.netstack_fd()`, call `guest.dns_vsock_fd().ok()`, spawn `SpeckNet::new(net_config, Some(53)).spawn(netstack_fd, dns_vsock_fd, vec![], Some(port_map_rx))`.
</objective>

    crates/speck-vz/src/guest.rs — confirm Guest::netstack_fd(), Guest::dns_vsock_fd(), and Guest::set_port_map_channel() signatures (netstack_fd returns Result<RawFd, Error>, dns_vsock_fd returns Result<RawFd, Error>, set_port_map_channel takes mpsc::Sender<speck_net::PortMapConfig>).
  </read_first>
  <action>
    After the line `guest.wait_for_ready()?;` and before `spinner.set_message("Starting Docker API server...");`, insert the following wiring block in run_up:

    1. Create a tokio mpsc channel for dynamic port maps:
       `let (port_map_tx, port_map_rx) = tokio::sync::mpsc::channel::<speck_net::PortMapConfig>(64);`

    2. Call `guest.set_port_map_channel(port_map_tx)?;` — this sends a `SetPortMapChannel` command to VmThread which stores the sender in `ctrl.port_map_tx`. Must be called before SpeckDockerd starts so that the first `container_start` call finds a live channel. Returns `Result<(), speck_vz::error::Error>` — propagate with `?`.

    3. Retrieve the netstack fd: `let netstack_fd = guest.netstack_fd()?;`

    4. Retrieve the DNS vsock fd (best-effort, DNS proxy is optional):
       `let dns_vsock_fd = guest.dns_vsock_fd().ok();`

    5. Spawn SpeckNet:
       ```
       let net_config = speck_net::config::NetworkConfig::default();
       let _netstack_handles = speck_net::SpeckNet::new(net_config, Some(53))
           .spawn(netstack_fd, dns_vsock_fd, vec![], Some(port_map_rx));
       ```
       The `_netstack_handles` binding keeps the JoinHandles alive without requiring them to be awaited. The handles are tokio tasks that detach on drop — they terminate naturally when the netstack fd is closed (when Guest drops on ctrl+c).

    Note: `SpeckNet::spawn` is a tokio async context call. Confirm run_up is an async fn (it is — it returns anyhow::Result<()> with `tokio::signal::ctrl_c().await?`). SpeckNet::spawn takes a RawFd and internally wraps it in `tokio::io::unix::AsyncFd`, so it must be called within a tokio runtime — the run_up async fn satisfies this.

    Add `use speck_net;` or prefix all speck_net calls with the full path (prefer the latter since it is clearer and avoids ambiguity with the existing speck_net::config::NetworkConfig import from Task 1).

    Pitfall: Do NOT call `set_port_map_channel` before `guest.start()` — the VM must be in Running state for port map commands to succeed. The ordering `start → wait_for_ready → set_port_map_channel → SpeckNet::spawn → SpeckDockerd::start` is correct.
  </action>
