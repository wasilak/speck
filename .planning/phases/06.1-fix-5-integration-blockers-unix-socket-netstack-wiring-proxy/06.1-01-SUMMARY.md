## What Was Built

### Task 1 — vm_thread.rs changes

Four targeted changes to `crates/speck-vz/src/vm_thread.rs`:

1. **`VmCommand::SetPortMapChannel` enum variant** — carries `tx: mpsc::Sender<PortMapConfig>` and `reply: oneshot::Sender<Result<(), Error>>`. Enables the netstack to register its channel with the VM thread after startup (required by Plan 06.1-02).

2. **`SetPortMapChannel` handler** in the `while let Some(cmd)` match loop — locks control, sets `ctrl.port_map_tx = Some(tx)`, drops the lock, replies `Ok(())`.

3. **`VmThread::clone_cmd_sender()`** — `pub(crate)` method returning a clone of `self.sender`. Enables `guest.rs` connector closures to send `VmCommand::VsockConnect` from `std::thread` context without holding a borrow of `VmThread`.

4. **`VmThread::set_port_map_channel()`** — public method using the same `send_blocking` pattern as `add_port_map` and `wait_for_ready`.

5. **Removed VirtioFS if-gate** — `configure_virtiofs_devices` is now called unconditionally in `do_start`. The speck-home VirtioFS device must always be present for Ryuk and testcontainers to function even when no user volume mounts are requested.

### Task 2 — guest.rs changes

1. **`Guest::vsock_connector_for_port(port)`** — private method returning `impl Fn() -> Result<VzSocket, Error> + Send + 'static`. The closure captures a cloned `mpsc::Sender<VmCommand>` and, on each invocation, creates a `tokio::sync::oneshot` channel, sends `VmCommand::VsockConnect` via `blocking_send`, and returns the result from `blocking_recv`. Safe only from `std::thread` context (documented in code comment per T-06.1-02 threat).

2. **`containerd_unix_proxy()` rewritten** — replaced `if let Ok((stream, _)) = listener.accept()` single-accept with a persistent `loop { match listener.accept() { Ok(...) => { ... } Err(e) => { tracing::warn!(...); break; } } }` pattern. Each accepted Unix client gets its own fresh vsock connection via `connector()`.

3. **`buildkitd_unix_proxy()` rewritten** — identical loop pattern applied.

4. **`Guest::set_port_map_channel()`** — public delegation method to `VmThread::set_port_map_channel`. Required by `up.rs` in Plan 06.1-02.
