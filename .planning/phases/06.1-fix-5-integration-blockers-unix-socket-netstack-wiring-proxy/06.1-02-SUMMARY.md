# Phase 06.1 Plan 2: Fix speck_home Creation and Wire Netstack in run_up — Summary

`run_up` now creates speck_home before use, passes it and the network config to GuestConfig, and spawns SpeckNet with a dynamic port-map channel after `wait_for_ready()`.

## What Was Built

### Changes to `crates/speck-cli/src/commands/up.rs`

1. **`std::fs::create_dir_all(speck_home)`** — first fallible operation in `run_up`, ensuring the VirtioFS-shared directory exists before `Guest::new()` and `Guest::start()`. Uses `anyhow::Context` for an actionable error message.

2. **GuestConfig builder extensions:**
   - `.speck_home(speck_home)` — passes the CLI-resolved path so GuestConfig.speck_home matches `$SPECK_HOME`, eliminating divergence with the `default_speck_home()` fallback
   - `.network(NetworkConfig::default())` — enables `VZFileHandleNetworkDeviceAttachment` in `vm_thread.rs do_start`; without this the guest has no network device
   - `.dns_vsock_port(53)` — after VM start, `do_start` connects to guest vsock port 53 and stores the fd in `ctrl.dns_vsock_fd` for SpeckNet's DNS proxy

3. **SpeckNet wiring block (after `wait_for_ready()`, before `SpeckDockerd::start`):**
   - `tokio::sync::mpsc::channel::<speck_net::PortMapConfig>(64)` — creates port-map channel
   - `guest.set_port_map_channel(port_map_tx)?` — registers sender with VM thread (delegation to `VmThread::set_port_map_channel` added in 06.1-01)
   - `guest.netstack_fd()?` — retrieves the socketpair fd for the smoltcp device
   - `guest.dns_vsock_fd().ok()` — retrieves the DNS vsock fd, best-effort (None on failure)
   - `SpeckNet::new(net_config, Some(53)).spawn(netstack_fd, dns_vsock_fd, vec![], Some(port_map_rx))` — spawns the smoltcp poll loop and optional DNS proxy as detached tokio tasks

### Dependency addition

Added `speck-net = { path = "../speck-net" }` to `crates/speck-cli/Cargo.toml` — required for `SpeckNet`, `speck_net::config::NetworkConfig`, and `speck_net::PortMapConfig` at the CLI level.
