# Phase 06.1 Plan 3: Apply Port Bindings in start() Handler Summary

**One-liner:** `start()` now reads the `speck.port_bindings` JSON label and calls `guest.add_port_map(hp, cp)` per binding — wiring create-time port declarations to the live netstack.

## What Was Built

The `start()` async handler in `crates/speck-dockerd/src/handlers/containers.rs` previously
called `client.task_start(&id)` and then emitted an event — discarding the `info.labels` map
it had already retrieved via `container_get`. Published ports were stored in the label
`speck.port_bindings` by `create()` (as `serde_json::to_string` of a
`HashMap<String, Vec<PortBindingBody>>`), but `start()` never read them, making all `-p`
port mappings silently non-functional.

After this fix the handler:
1. Checks `info.labels.get("speck.port_bindings")`.
2. On presence, deserialises with `serde_json::from_str::<HashMap<String, Vec<PortBindingBody>>>`.
3. Iterates the map; for each `"container_port/proto"` key, extracts the numeric container port.
4. For each `PortBindingBody` with a valid `host_port`, calls `state.guest.add_port_map(hp, cp)`.
5. All parse failures and `add_port_map` errors are `tracing::warn!`-logged and skipped — the
   HTTP response remains `204 No Content` regardless.

## Deviations from Plan

None — plan executed exactly as written. The parse path used
`split('/').next().and_then(|s| s.parse().ok())` as a single-expression alternative to the
two-step split + parse the plan described; semantics are identical.
