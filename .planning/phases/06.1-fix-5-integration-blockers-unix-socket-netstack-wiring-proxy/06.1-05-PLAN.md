<objective>
Fix two correctness gaps in the `speck-vz` crate:

**CR-02 (WARNING):** `do_start` creates a `std::sync::mpsc::channel::<VmStateEvent>()` but immediately drops the receiver (`_delegate_rx` is a local variable that goes out of scope when `do_start` returns at line 582). All VM lifecycle notifications — crash, OOM, kernel panic — are silently discarded. `VmControl.state` never transitions from `Running` on unplanned VM termination. This prevents any health-check loop or Docker API `/info` call from detecting VM death.

Fix: Rename `_delegate_rx` to `delegate_rx`, clone the `control` Arc for a drain thread, and spawn a `std::thread::spawn` that owns the receiver. The thread loops on `delegate_rx.recv()` and sets `ctrl.state = InternalState::Stopped` on any received event. The thread exits automatically when `VmDelegate` drops (its sender is dropped with the ObjC object), so no explicit cancellation is needed.

**CR-03 (WARNING):** `crates/speck-vz/Cargo.toml` lists `"VZBootLoader"` and `"VZPlatformConfiguration"` as explicit feature entries but `vm_thread.rs` uses `VZLinuxBootLoader`, `VZGenericPlatformConfiguration`, `VZVirtioEntropyDeviceConfiguration`, and `VZEntropyDeviceConfiguration` — none of which have matching explicit entries. The build currently passes via transitive feature cascading. A patch release of `objc2-virtualization` that reorganises feature dependencies could silently break the build.

Fix: Add the four missing feature strings as explicit entries to the `objc2-virtualization` features list in `Cargo.toml`. Keep the existing `"VZBootLoader"` and `"VZPlatformConfiguration"` entries — they are base-class features and should remain.

Purpose: CR-02 enables VM health visibility (Docker `/info`, future watchdog loops). CR-03 makes the build hermetic against upstream feature reorganisations.

Output: Modified `vm_thread.rs` (delegate drain thread) and `Cargo.toml` (four new feature entries). No public API changes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ObjC VmDelegate callbacks → drain thread | VmStateEvent values cross from the ObjC dispatch queue into a Rust std::thread via std::sync::mpsc |
| drain thread → VmControl mutex | The drain thread acquires the same mutex as do_start and do_stop; lock contention is minimal (VM death is a rare one-shot event) |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
