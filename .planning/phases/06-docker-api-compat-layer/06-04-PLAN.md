Return 101 response with headers Upgrade: tcp, Connection: Upgrade, Content-Type: application/vnd.docker.raw-stream. In spawned upgrade task: get TokioIo-wrapped Upgraded. Call ContainerdClient to get task attach stream. Bridge: read stdout/stderr from containerd → encode_frame(1, chunk) or encode_frame(2, chunk) if not tty; read stdin frames via decode_frame → forward to containerd stdin. Check tty query param — if tty=true, skip framing (raw bytes both directions).
    - container_logs handler: GET /containers/{id}/logs — query params: stdout, stderr, tail, follow, timestamps. Call containerd logs API or task attach (read-only). For non-streaming (follow=false): return buffered logs with multiplexed framing. For follow=true: return chunked response with encode_frame chunks as they arrive. Content-Type: application/vnd.docker.raw-stream. Non-TTY mode only (logs are always framed per Docker API spec).
    - container_archive_get (GET /containers/{id}/archive): query param path=. Exec `tar -c -C <container_path> .` in container via containerd exec; stream stdout as chunked response. Return header X-Docker-Container-Path-Stat (JSON base64 of file stat).
    - container_archive_put (POST /containers/{id}/archive): read tar body, exec `tar -x -C <container_path>` in container with the body piped to stdin.

    - image_push: POST /images/{name}/push — forward to containerd image push. Return chunked JSON progress.
    - image_remove: DELETE /images/{name} — call containerd_client.image_delete(name). Return JSON [{"Untagged": name}].

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| X-Registry-Auth header → registry_auth.rs | Attacker-controlled base64 JSON; must not crash on malformed input |
| ~/.docker/config.json → registry_auth.rs | Host filesystem read; path is fixed; no path traversal possible |
| events SSE stream → broadcast channel | Memory-bounded broadcast; subscriber lag must not grow unboundedly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04-01 | Information Disclosure | registry_auth.rs — password from ~/.docker/config.json | mitigate | Password loaded into memory only for duration of image pull; never logged (tracing::debug! logs username only); field not included in any tracing span |
| T-06-04-02 | Tampering | X-Registry-Auth header — malformed base64 | mitigate | decode_registry_auth_header returns Option<RegistryCredentials>; None → fall through to config.json; no panic on malformed base64 (use base64::decode().ok()) |
| T-06-04-03 | Denial of Service | events broadcast channel backlog | mitigate | BroadcastStream with capacity 256; slow/lagged subscribers receive RecvError::Lagged (frames skipped) rather than blocking the sender |
| T-06-04-04 | Tampering | volume name in POST /volumes/create | mitigate | Validate volume name matches `^[a-zA-Z0-9][a-zA-Z0-9_.-]*$` before storing; reject with 400 on violation |
| T-06-04-05 | Tampering | network name injection | mitigate | Validate network name non-empty; reject names containing path separators or shell metacharacters |
| T-06-04-SC | Tampering | tokio-stream cargo install | mitigate | Official tokio ecosystem crate; verified in broader tokio audit |
</threat_model>
