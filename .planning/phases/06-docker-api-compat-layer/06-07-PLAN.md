<objective>
Implement `spk build` / `POST /build` via in-guest BuildKit. The handler accepts a Docker-format build context (tar archive), calls BuildKit's gRPC Solve API via vsock port 9002, and streams JSON progress back to the client. Guest::buildkitd_unix_proxy() is the new public method mirroring Phase 5's containerd_unix_proxy().

Purpose: Satisfies BUILD-01 (spk build works), BUILD-02 (BuildKit handles multi-stage/cache natively via SolveRequest options), BUILD-03 (BuildKit LLB cache is on the data disk — survives VM restarts). Per D-10, `spk build` routes through `POST /build` on the Docker socket so both docker build and spk build use the same code path.

Output: vendored BuildKit proto, tonic codegen build.rs, buildkit.rs (typed gRPC client), build.rs handler, buildkitd_unix_proxy() in guest.rs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| POST /build body (tar) → BuildKit | Untrusted build context tar sent to buildkitd which runs in the VM guest |
| buildkitd gRPC response → JSON stream | BuildKit log output streamed back to client; may contain arbitrary text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-07-01 | Tampering | build context tar body size | mitigate | Apply body size limit in axum extract: use axum::extract::DefaultBodyLimit or tower-http ContentLengthLimit; cap at 10GB (matching Docker's default) |
| T-06-07-02 | Information Disclosure | registry credentials in SolveRequest frontend_attrs | mitigate | Auth tokens passed to SolveRequest exporters only if user explicitly provides --build-arg; never log frontend_attrs that may contain secrets |
| T-06-07-03 | Denial of Service | long-running build holding connection | accept | Build is bounded by buildkitd timeout (configurable in buildkitd config); host-side connection is HTTP chunked and will be cleaned up on client disconnect |
| T-06-07-04 | Tampering | dockerfile path traversal in query param | mitigate | dockerfile query param value is only passed as frontend_attrs["filename"] to BuildKit — BuildKit resolves it relative to the tar context; host-side no file I/O on this value |
</threat_model>
