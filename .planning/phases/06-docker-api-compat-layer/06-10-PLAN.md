<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Secrets → release workflow | Signing certificates and notarization keys are secrets; must not be logged or exposed |
| Homebrew tap → end user machine | Homebrew downloads and installs the binary; entitlement preservation is critical |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-10-01 | Information Disclosure | Developer ID certificate in GitHub Secrets | mitigate | Secrets accessed only via ${{ secrets.* }} in workflow steps; never echo'd or logged; build.keychain deleted at end of job |
| T-06-10-02 | Tampering | Homebrew Formula sha256 placeholder | accept | sha256 placeholder is updated when the first release is cut; Homebrew formula SHA verification prevents tampered downloads post-release |
| T-06-10-03 | Spoofing | Ad-hoc codesign for dev builds | accept | Ad-hoc signature (-s -) does not chain to Apple's PKI; it only proves the binary has not been modified since signing. The virtualization entitlement is enforced by macOS kernel regardless of signing chain. For production, Developer ID signing is required per DIST-02. |
| T-06-10-04 | Tampering | Release binary supply chain | mitigate | Release workflow runs on GitHub-managed macos-latest runner (not self-hosted); cargo.lock pins all dependencies; notarization scans for known malware |
</threat_model>
