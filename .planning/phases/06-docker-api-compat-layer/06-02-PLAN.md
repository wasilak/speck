<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External client → Unix socket | Docker CLI, Compose, testcontainers connect to speck.sock; untrusted HTTP requests cross here |
| speck-dockerd → containerd gRPC | Outbound; containerd is trusted (in-guest) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Spoofing | speck.sock permissions | mitigate | Socket bound with mode 0600 via std::os::unix::fs::PermissionsExt::from_mode(0o600) in server.rs; only owner process can connect |
| T-06-02-02 | Tampering | Stale socket file at startup | mitigate | server::serve() removes stale socket with std::fs::remove_file before UnixListener::bind; prevents socket hijack from previous run |
| T-06-02-03 | Denial of Service | Unbounded accept loop | accept | tokio::spawn per connection; OS limits total connections; no per-IP rate limiting needed for local socket |
| T-06-02-04 | Information Disclosure | AppState containerd_proxy_path visible | accept | Path is a temp file in /tmp owned by current user; no sensitive data in the path itself |
| T-06-02-SC | Tampering | cargo install axum, hyper-util, tonic | mitigate | All packages verified in RESEARCH.md Package Legitimacy Audit as OK; no blocking checkpoint required |
</threat_model>
