<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI user input → DockerClient HTTP requests | User-supplied container names, image refs, port specs, volume paths sent to Docker socket |
| spk exec stdin → container exec | Arbitrary commands piped to exec stream |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-08-01 | Tampering | -v volume flag path traversal | mitigate | cli/run.rs: validate host_path in RunArgs.volume before sending to dockerd; reject paths with ".." components; reject if path does not exist (std::fs::metadata check) |
| T-06-08-02 | Information Disclosure | DOCKER_HOST printed to stdout | accept | DOCKER_HOST value is the Unix socket path in $SPECK_HOME; not sensitive; printed to stdout by design for user convenience |
| T-06-08-03 | Spoofing | CLI reads SPECK_HOME env var | accept | SPECK_HOME is a user-controlled path; the CLI runs as the current user and only writes to paths owned by that user |
| T-06-08-04 | Elevation of Privilege | spk exec allows arbitrary commands in container | accept | exec commands run inside the container namespace enforced by containerd/runc; no host privilege escalation possible from inside the container |
</threat_model>
