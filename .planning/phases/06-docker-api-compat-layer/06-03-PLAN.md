<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request body → container_create handler | Untrusted Docker API input: container names, image refs, env vars, mount specs |
| exec_start upgraded stream → containerd exec | Bidirectional I/O; commands run inside container |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Tampering | container name in ContainerCreateBody | mitigate | Validate container name matches `^[a-zA-Z0-9][a-zA-Z0-9_.-]+$` before passing to containerd; return 400 BadRequest on violation |
| T-06-03-02 | Tampering | image ref in ContainerCreateBody | mitigate | Validate image ref is non-empty and does not contain shell metacharacters; OCI reference parsing via containerd's own reference parser |
| T-06-03-03 | Elevation of Privilege | exec cmd passthrough to containerd | accept | Commands are passed verbatim to containerd exec which enforces container namespace boundary; no shell interpolation on host side (containerd enforces isolation) |
| T-06-03-04 | Information Disclosure | container env vars in inspect response | accept | Env vars may contain secrets but are returned by design per Docker API v1.44 spec; callers are authenticated via socket ownership |
| T-06-03-05 | Denial of Service | exec_store unbounded growth | mitigate | Cap exec_store at 1000 entries; evict oldest on overflow; log warning via tracing::warn! |
| T-06-03-SC | Tampering | cargo install containerd-client, uuid | mitigate | Verify containerd-client via cargo search before adding; uuid is a well-known crate (tokio ecosystem) |
</threat_model>
