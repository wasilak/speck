<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arg → trace_dns | The `hostname` argument from `spk doctor dns <hostname>` crosses from user-provided CLI input into subprocess execution — highest injection risk in this phase |
| Docker socket → container exec | Container created with user-supplied hostname in Cmd array; array form prevents shell interpretation |
| host process → /usr/bin/nslookup | Host-side comparison also uses .arg(hostname) array form |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering | `trace_dns` hostname arg (DOCTOR-03 exec path) | mitigate | Validate hostname with chars().any() check before any subprocess call; pass to Command::new("nslookup").arg(hostname) — never via bash -c or string interpolation. Source assertion test dns_hostname_not_shell_injected verifies the pattern is present in production code. |
| T-13-02 | Spoofing | control.sock connect in check_vm_running | mitigate | After connecting, read at least 1 byte (PONG drain) to confirm daemon is actively responding, not just a stale socket file. |
| T-13-03 | DoS | Hanging async checks | mitigate | Both check_vm_running and check_docker_socket are wrapped in tokio::time::timeout(Duration::from_secs(2), ...) so a non-responsive daemon cannot hang the doctor command. |
| T-13-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase — all dependencies are existing workspace deps per RESEARCH.md package legitimacy audit. |
</threat_model>
