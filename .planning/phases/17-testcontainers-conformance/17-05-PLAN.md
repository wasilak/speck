<objective>
Replace the raw vsock byte-bridge (`docker_api_unix_proxy()`) with the production SpeckDockerd axum server in the `spk up` command path. Also fix `image_push` error propagation and network connect/disconnect validation for nonexistent containers.

**Purpose:** Currently `spk up` uses a raw byte-bridge proxy (`docker_api_unix_proxy`) that forwards raw bytes between the Docker socket and the in-guest containerd socket. This bypasses the SpeckDockerd axum server entirely — none of the persistence, correct request routing, or error handling runs. This plan flips the default so SpeckDockerd serves the Docker socket directly.

**Output:** Updated `up.rs`, `images.rs`, `networks.rs`.
</objective>

    2. **Replace the proxy call** with `SpeckDockerd::start()`. The `SpeckDockerd` struct needs:
       - `sock_path: PathBuf` — the Docker API socket path (currently the socket path already used, typically something like `{SPECK_HOME}/speck.sock` or `{run_dir}/docker.sock`). Use the exact same path the proxy used so clients find the socket at the same location.

    ```rust
    tracing::info!("Docker API server started at {}", sock_path.display());
    ```

    6. **Keep the socket path the same**: Verify the Docker socket path variable name is the same one used by the proxy. The path typically comes from `self.state.home_dir()` or similar. Don't change the path — only change what serves it.

    - How is cleanup/stop handled?

      ```rust
        }
    }
      ```

    ```rust
    match state.containerd_client().container_get(&container_id).await {
        Ok(_) => { /* proceed */ }
    ```
