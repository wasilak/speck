    **Approach selection** (decide based on what's available in the codebase):

    **Option A — containerd gRPC `ReadTask` API** (preferred if the protobuf types exist): Use the containerd `TaskServiceClient` (already wrapped in this struct) to call `read()` on the task. The `TasksReadRequest` takes `container_id`, `fifo_id` (e.g., "stdout", "stderr"), and `offset`/`limit`. Return concatenated stdout+stderr output.

  <action>
    In `attach.rs`, update the `container_logs_handler` (the axum handler for `GET /containers/{id}/logs`):

    **Current behavior**: Returns a static string like `format!("container {id} status {:?}\n")`.

    **New behavior**: Calls `state.containerd_client().task_logs(&id).await` to get the output bytes, then encodes the bytes through `encode_frame` with the correct stream type (1=stdout, 2=stderr), and returns the multiplexed bytes.

    Steps:

    1. Get the container ID from the request path (already works).

    2. Call task_logs:
    ```rust
    let output = state.containerd_client().task_logs(&id).await
        .unwrap_or_else(|e| format!("container {id} error: {e}\n").into_bytes());
    ```

    3. Encode through `encode_frame`. The `encode_frame` function signature from stream.rs takes stdout bytes (Vec<u8>) and stderr bytes (Vec<u8>). The task_logs returns combined output — separate stdout from stderr by calling task_logs twice (once for each stream), or encode the combined output as stdout (stream type 1).

    Check the `encode_frame` signature — if it takes `(stdout: Vec<u8>, stderr: Vec<u8>)`:
    - If `task_logs` returns separated output per stream, pass appropriately.
    - If `task_logs` returns combined output, pass combined data as stdout and empty Vec for stderr.
    - Fallback: return the raw output as a plain text response (without multiplexing) if encode_frame proves incompatible.

    4. Return as `(StatusCode, [(header, value)], Vec<u8>)` or axum response type matching the existing handler's return type.

    **Key constraint (per CONTEXT.md CONF-05)**: "Use `encode_frame` to wrap container stdout/stderr from containerd's task I/O." The `encode_frame` function already exists in `stream.rs` and supports the Docker 8-byte multiplexed frame format. Use it.

    **Edge cases**:
    - Empty output: return empty multiplexed frames (just a zero-length body)
    - Error from containerd: return the status fallback string as non-multiplexed plain text
    - Non-existent container: the handler already returns 404 before reaching this code

    Determine the exact axum return types — look at other handlers in this file that return binary/streaming responses.
