<objective>
Create the SQLite persistence foundation for all Docker API state: storage module, schema migration, CRUD operations, exec restart reconciliation, and wiring into SpeckDockerd.

**Purpose:** Replace in-memory HashMap stores with SQLite-backed persistence so volumes, networks, exec sessions, and container metadata survive daemon restarts (CONF-02). Exec restart reconciliation (CONF-04) is a startup step that runs immediately after DB open.

- Updated `lib.rs` -- `SpeckDockerd::start()` opens storage, runs reconcile, passes to AppState
- Updated `Cargo.toml` -- `rusqlite` dependency added
</objective>

    Add `rusqlite = { version = "0.32", features = ["bundled"] }` to `[dependencies]` in Cargo.toml, following the existing version pattern (e.g. `serde = { version = "1"`, `axum = "0.8.9"`). Keep the `[build-dependencies]` and `[dev-dependencies]` sections unchanged.

    Create `crates/speck-dockerd/src/storage.rs` as a new file. The imports follow the `containerd_client.rs` pattern: `use std::collections::HashMap; use std::path::Path; use serde_json::Value; use crate::error::{DockerApiError, Result};`.

    The `Storage` struct wraps `rusqlite::Connection`. Constructor `Storage::open(path: impl AsRef<Path>) -> Result<Self>` calls `Connection::open`, maps errors to `DockerApiError::Internal`, calls `self.migrate()`, returns Self.

    The `migrate()` private method calls `self.conn.execute_batch(...)` with `CREATE TABLE IF NOT EXISTS` for exactly these four tables (column names and types MUST match the RESEARCH.md schema):

    1. `volumes (name TEXT PRIMARY KEY, driver TEXT NOT NULL DEFAULT 'local', mountpoint TEXT NOT NULL, created_at TEXT)`
    2. `networks (id TEXT PRIMARY KEY, name TEXT NOT NULL, driver TEXT NOT NULL DEFAULT 'bridge', scope TEXT NOT NULL DEFAULT 'local')`
    3. `exec_sessions (id TEXT PRIMARY KEY, container_id TEXT NOT NULL, cmd TEXT NOT NULL, env TEXT NOT NULL DEFAULT '[]', attach_stdin INTEGER NOT NULL DEFAULT 0, attach_stdout INTEGER NOT NULL DEFAULT 1, attach_stderr INTEGER NOT NULL DEFAULT 1, tty INTEGER NOT NULL DEFAULT 0, running INTEGER NOT NULL DEFAULT 0, exit_code INTEGER)`
    4. `container_meta (id TEXT PRIMARY KEY, image TEXT NOT NULL, create_body_json TEXT NOT NULL, port_bindings_json TEXT, created_at TEXT NOT NULL)`

    Error mapping for all rusqlite calls: `.map_err(|e| DockerApiError::Internal(format!("context: {e}")))`.

    Implement these public methods, each following the query_map / execute pattern from PATTERNS.md:

    - `load_volumes(&self) -> Result<HashMap<String, VolumeSummary>>` — SELECT all, map to VolumeSummary { name, driver, mountpoint, created_at }
    - `save_volume(&self, volume: &VolumeSummary) -> Result<()>` — INSERT OR REPLACE with rusqlite::params!
    - `delete_volume(&self, name: &str) -> Result<()>` — DELETE WHERE name = ?1
    - `load_networks(&self) -> Result<HashMap<String, NetworkSummary>>` — SELECT all, map to NetworkSummary { id, name, driver, scope }
    - `save_network(&self, network: &NetworkSummary) -> Result<()>` — INSERT OR REPLACE
    - `delete_network(&self, id: &str) -> Result<()>` — DELETE WHERE id = ?1
    - `save_exec(&self, spec: &ExecSpec) -> Result<()>` — INSERT OR REPLACE into exec_sessions, serializing cmd to JSON string (serde_json::to_string), env to JSON string, bools to 0/1, exit_code as Optional<i64>
    - `update_exec(&self, spec: &ExecSpec) -> Result<()>` — UPDATE exec_sessions SET running = ?1, exit_code = ?2 WHERE id = ?3
    - `reconcile_execs(&self) -> Result<usize>` — UPDATE exec_sessions SET running = 0, exit_code = -1 WHERE running = 1; return number of rows changed
    - `save_container_meta(&self, id: &str, image: &str, create_body_json: &str, port_bindings_json: &Option<String>, created_at: &str) -> Result<()>` — INSERT OR REPLACE into container_meta
    - `load_port_bindings(&self, id: &str) -> Result<Option<HashMap<String, Vec<PortBindingBody>>>>` — SELECT port_bindings_json FROM container_meta WHERE id = ?1, deserialize with serde_json. Return Ok(None) if no row or NULL port_bindings_json.

    For `load_port_bindings`, the `PortBindingBody` type is defined in `crate::handlers::containers::PortBindingBody`. Import it as `use crate::handlers::containers::PortBindingBody;`.

    For `save_exec`, serialize `cmd` as JSON array string (serde_json::to_string) and `env` as JSON array string. For bool fields, use `if spec.attach_stdin { 1 } else { 0 }`.

    For the `ExecSpec` type, import from `crate::state::ExecSpec`. Add `use crate::state::ExecSpec;`.

    Add unit tests at the bottom of storage.rs using an in-memory SQLite database (`Connection::open_in_memory()`) to verify:
    - `test_storage_volume_roundtrip`: save and load a volume, assert fields match
    - `test_storage_network_roundtrip`: save and load a network
    - `test_storage_exec_save_update`: save exec, update it, verify change
    - `test_storage_reconcile_execs`: save two execs (one running, one not), reconcile, verify running ones reset
    - `test_storage_container_meta_roundtrip`: save container_meta with port_bindings, load them back
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker API client → SpeckDockerd | Unix-socket-only client sends JSON payloads (container names, volume names, network names, image refs) |
| SpeckDockerd → SQLite | Storage module writes to local file via rusqlite |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Injection | storage.rs SQL queries | mitigate | All queries use positional parameters (`?1`, `?2`) via `rusqlite::params!` macro — never string interpolation. Names pre-validated by handler `validate_*` functions before reaching storage. |
| T-17-02 | Denial of Service | storage.rs SQLite writes | accept | Local Unix socket, not network-exposed. ExecStore is already capped at MAX_ENTRIES=1000; volumes/networks are user-created, bounded by disk. |
| T-17-03 | Tampering | cargo installs | mitigate | No new crates beyond `rusqlite` (well-established, 2.5K+ GitHub stars, bundled SQLite from sqlite.org). See package legitimacy gate. |
</threat_model>
