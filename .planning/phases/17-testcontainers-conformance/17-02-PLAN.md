<objective>
Wire persistent storage into the volume, network, and exec handlers so that state survives daemon restarts (CONF-03) and exec sessions are tracked through their lifecycle (CONF-04).

**Purpose:** Before this plan, volume/network/exec state lived only in in-memory HashMaps inside AppState. After this plan, every create/remove/update operation also persists to SQLite. Network validation in connect/disconnect uses the persisted network list instead of in-memory-only. Exec sessions are saved on create and updated on start.

**Output:** Updated handler modules in `handlers/volumes.rs`, `handlers/networks.rs`, `handlers/exec.rs`.
</objective>

  <action>
    In `volumes.rs`, in the `create_volume_handler` function (or equivalent route handler that creates volumes):

    After the volume is created and inserted into `state.volume_store`, add:
    ```rust
    // persist to SQLite
    if let Ok(storage) = state.storage.lock() {
        let vol = VolumeSummary {
            name: body.Name.clone().unwrap_or_default(),
            driver: "local".to_string(),
            mountpoint: format!("/var/lib/speck/volumes/{}", body.Name.as_deref().unwrap_or_default()),
            created_at: chrono::Utc::now().to_rfc3339(),
        };
        let _ = storage.save_volume(&vol);
    }
    ```

    In the `remove_volume_handler` / `delete_volume_handler` function:

    Add after removal from in-memory store:
    ```rust
    if let Ok(storage) = state.storage.lock() {
        let _ = storage.delete_volume(&name);
    }
    ```

    If there is a `VolumeSummary` struct definition or import in this file, keep it. If `VolumeSummary` comes from `speck_core`, import it: `use speck_core::volume::VolumeSummary;`.

    Use `.lock()` on `Arc<Mutex<Storage>>` — this requires `if let Ok(storage) = state.storage.lock()` pattern. Log failures silently (they're non-fatal — the in-memory state still works). No wrap in `?` — storage failures should not abort the HTTP request.

    Do NOT use `chrono` if not already in the dependency tree — use `speck_core::now()` or whatever time utility exists. If none exists, use a simple timestamp format.

    Check what time type is available in the crate — if `chrono` is not a dependency, look for `time` or use `std::time::SystemTime::now().duration_since(UNIX_EPOCH)` and format manually as RFC3339.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker API client → volume/network/exec handlers | JSON payloads with names, IDs across Unix socket |
| Handlers → SQLite (via Storage) | Structured data with positional parameters |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-04 | Tampering | Network name through handlers to SQL | mitigate | Names already validated by `validate_network_name()` before reaching handler. Storage uses `INSERT OR REPLACE` with positional params — SQL injection impossible. |
| T-17-05 | Tampering | Volume name through handlers to SQL | mitigate | Names validated by `validate_volume_name()` (alphanumeric + underscore/hyphen pattern) before reaching handler. |
| T-17-06 | Spoofing | Unix socket identity | accept | Local socket only; no authentication required per Docker API spec for local socket. ASVS L1 accepts this. |
</threat_model>
