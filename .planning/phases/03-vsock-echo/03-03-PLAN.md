    **vsock_echo.rs** — Create the guest-side echo server using raw `libc` AF_VSOCK syscalls.

    The server:
    1. Creates a socket with `libc::socket(AF_VSOCK, SOCK_STREAM, 0)` — AF_VSOCK is 40 on aarch64 Linux; `libc` already defines `AF_VSOCK` if the target OS is Linux.
    2. Binds to `VMADDR_CID_ANY` + the given port:
       ```rust
       let addr = libc::sockaddr_vm {
           svm_family: AF_VSOCK as u16,
           svm_reserved1: 0,
           svm_port: port as u32,
           svm_cid: libc::VMADDR_CID_ANY,
       };
       ```
       Cast the addr to `*const libc::sockaddr` and pass with `std::mem::size_of::<libc::sockaddr_vm>()` as socklen_t (16 bytes on aarch64).
    3. Calls `libc::listen(fd, 1)` with backlog 1 (single connection for Phase 3).
    4. Accepts: `let client = libc::accept(fd, std::ptr::null_mut(), std::ptr::null_mut())`.
       For Phase 3 we don't need the peer address (VMCID is always `VMADDR_CID_HOST`).
    5. Echo loop: `read(client, buf, BUF_SIZE)` → if >0, `write(client, buf, n)`.
       Use a 4KB buffer (`[0u8; 4096]`). Exit on read returning 0 (EOF) or <0 (error).
    6. On EOF: `libc::close(client)` and return (single-shot echo for Phase 3).
    7. On error: close client, return Err.

    Error handling pattern: each syscall checks `< 0`, calls `io::Error::last_os_error()`.
    Return `io::Result<()>` for simplicity.

    Use the target-gated pattern so the module only compiles on Linux:
    ```rust
    #![cfg(target_os = "linux")]
    ```
    This is critical — the vminitd binary target is `aarch64-unknown-linux-musl`, but the crate may also be checked on macOS (the host build).

    The function signature:
    ```rust
    /// Blocking echo server on AF_VSOCK `port`.
    /// Accepts exactly one connection and echoes until EOF.
    pub fn serve(port: u32) -> std::io::Result<()>;
    ```

    Import note: `AF_VSOCK` and `VMADDR_CID_ANY` are in libc 0.2.x but are only available on `target_os = "linux"`. The compiler will only find them when building for the linux target.

    **lib.rs** — Add `#[cfg(target_os = "linux")] pub mod vsock_echo;`
    The `#[cfg]` gate prevents the module from being compiled on macOS (host build).

    ```rust

    //!
    //! Starts the vsock echo server on the port passed via kernel cmdline.
    //! Listens for one connection, echoes, then reboots (SIGTERM → exit).
    //!
    ```

    Wait — using `no_std` means we can't use `libc` crate either, since it depends on the C standard library. That makes the memory management and error handling extremely painful.

    Actually, for a musl static binary on Linux with `libc` crate, `#![no_main]` is needed but `#![no_std]` is NOT. Musl provides the full C standard library, and the `libc` crate works fine with `std`. PID 1 != no_std. Let me keep this as a normal `std` binary but with `#![no_main]` to avoid the `start` language item conflict.

    Actually, the simplest approach for PID 1 is:
    ```rust
    // vminitd — PID 1 guest init process
    #[cfg(target_os = "linux")]
    fn main() -> ! {
        // Parse cmdline for vsock_port=1234
        // Open /dev/kmsg for logging
        // Start vsock_echo::serve(port)
        // Handle SIGTERM for shutdown
    }
    ```

    But wait — `std` binary needs the standard startup. For a static musl binary, `std` works fine. We don't need `no_std`. The kernel starts `/init` and it runs as a normal userspace process.

    Let me rewrite simply:

    ```rust
    //! vminitd — PID 1 inside the speck micro-VM.
    //!
    //! Parses the kernel cmdline for `vsock_port=PORT`,
    //! starts the vsock echo server, echoes one connection, then exits.
    //!
    //! Built as a static musl binary, placed at /init in a cpio initrd.

    fn main() {
        // 1. Parse vsock_port from /proc/cmdline
        let port = parse_cmdline_vsock_port("/proc/cmdline").unwrap_or(1234);

        // 2. Signal handler for graceful shutdown
        //    We're PID 1 — signals don't work the same way.
        //    For Phase 3, just run the echo server and exit when done.

        // 3. Run the echo server
        match speck_guests::vsock_echo::serve(port) {
            Ok(()) => {},
            Err(e) => {
                // Print to /dev/kmsg (kernel log buffer)
                // For Phase 3 we don't have a proper log yet
                eprintln!("echo server error: {}", e);
            }
        }
    }

    fn parse_cmdline_vsock_port(path: &str) -> Option<u32> {
        let content = std::fs::read_to_string(path).ok()?;
        for word in content.split_whitespace() {
            if let Some(port_str) = word.strip_prefix("vsock_port=") {
                return port_str.parse::<u32>().ok();
            }
        }
        None
    }
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host ↔ guest vsock | Raw vsock socket carries data between host and micro-VM. Phase 3 has no authentication — any process on the host that can reach the vsock device can connect. |
| PID 1 signal handling | As PID 1, default signal handling differs from normal processes. SIGTERM is ignored unless explicit handlers are installed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | DoS | vsock_echo::serve | accept | Single-connection echo server. If connection hangs, the server blocks until the host disconnects or reset occurs. Acceptable for Phase 3 test plumbing. |
| T-03-03-02 | Spoofing | vsock_echo::serve | accept | No peer authentication. The server accepts any connection on its port. Acceptable for Phase 3; future gRPC/TLS will add auth. |
| T-03-03-03 | Denial of Service | No reaper | accept | vminitd does not reap orphaned children (there are none in Phase 3). Future phases with containerd will need a proper init that handles SIGCHLD. |
