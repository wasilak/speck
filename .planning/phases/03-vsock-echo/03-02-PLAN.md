    ```rust
    fn do_vsock_connect(&self, port: u32) -> Result<VzSocket, Error> {
        let device = self.socket_device
            .as_ref()
            .ok_or_else(|| Error::VsockConnect("no vsock device available — VM may not be running".into()))?;

        // Downcast base class to the concrete vsock device type.
        let vsock: &VZVirtioSocketDevice = device.downcast().map_err(|_| {
            Error::VsockConnect("socket device is not a VZVirtioSocketDevice".into())
        })?;

        // Synchronization primitive for the async callback.
        let (tx, rx) = std::sync::mpsc::channel();

        vsock.connectToPort_completionHandler(port, &block2::ConcreteBlock::new(move |connection: Option<Retained<VZVirtioSocketConnection>>, error: Option<&NSError>| {
            let result = match (connection, error) {
                (Some(conn), _) => {
                    let fd = conn.fileDescriptor();
                    // VzSocket::from_raw_fd takes ownership of the fd.
                    // The connection object is dropped here, but fd ownership
                    // has transferred to VzSocket.
                    Ok(unsafe { VzSocket::from_raw_fd(fd) })
                }
                (None, Some(err)) => Err(Error::VsockConnect(err.localizedDescription().to_string())),
                (None, None) => Err(Error::VsockConnect("unknown error: no connection and no error".into())),
            };
            let _ = tx.send(result);
        }));
        // ^ Per thread 31 of objc2-discuss: VZVirtioSocketDevice.connectToPort
        //   calls ObjC's -[VZVirtioSocketDevice connectToPort:completionHandler:]
        //   which takes a completion block (block2). The block retains the
        //   connection until fired; we fire it here synchronously because the
        //   vsock connect is dispatched on the serial queue.

        match rx.recv_timeout(Duration::from_secs(5)) {
            Ok(result) => result,
            Err(_) => Err(Error::VsockTimeout),
        }
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crossbeam channel ↔ dispatch queue | VmCommands enter via crossbeam channel; dispatch queue processes them. The vsock reply channels (oneshot) carry file descriptors across this boundary. |
| Raw fd from VZVirtioSocketConnection | The fd is extracted from an ObjC connection object inside a block2 callback, then wrapped in VzSocket which owns and closes it. |
| 5-second timeout | If the guest isn't listening, recv_timeout fires and returns VsockTimeout — the open fd is leaked. This is acceptable for Phase 3 (echo test); future phases add proper cancellation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | DoS | do_vsock_connect timeout | accept | 5-second timeout prevents indefinite blocking. If guest is not listening, fd from connectToPort is leaked (ObjC does not provide cancellation). Phase 4+ will handle this with gRPC lifecycle. |
| T-03-02-02 | Elevation of Privilege | do_vsock_connect | accept | No auth on vsock port in Phase 3. The echo server is test-only. Future phases add TLS over vsock. |
| T-03-02-03 | Information Disclosure | socket_device downcast | mitigate | Downcast uses VZSocketDevice → VZVirtioSocketDevice. If the wrong device type is extracted (shouldn't happen since we control config), the `map_err` returns a clear error instead of panic. |
</threat_model>
