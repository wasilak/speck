Create the Homebrew Cask formula at Casks/spk.rb and delete the obsolete Formula/speck.rb.

The Cask uses a pkg stanza so Homebrew calls installer -pkg rather than re-signing the binary. This is the mechanism that preserves the full Developer ID Application + notarization chain through Homebrew's install and upgrade flows (BREW-01, BREW-03). The Formula must be removed because a Formula and a Cask with the same name in the same tap cause brew to error.

  <action>
Create a new file at Casks/spk.rb using the Homebrew Cask DSL. The DSL entry point is `cask "spk" do` (lowercase, not `class Speck < Formula`).

Required fields in declaration order:
- `arch arm: "aarch64"` so that `#{arch}` interpolates to "aarch64" on Apple Silicon. This is the only supported architecture; no Intel/x86 path.
- `version "0.1.0"` — placeholder that the update-cask.yml workflow in the tap repo will replace on every release.
- `sha256 "<REPLACE_AFTER_FIRST_RELEASE>"` — placeholder string. The release CI computes the real SHA256 post-staple and dispatches the tap update workflow to substitute it. Do not use a real hash here.
- `url` pointing to the GitHub Release asset: `"https://github.com/speck-vm/speck/releases/download/v#{version}/spk-#{version}-#{arch}-apple-darwin.pkg"`. The release origin is speck-vm/speck (the main repo where tags are pushed); the tap is hosted separately at speck-runtime/homebrew-speck.
- `name "Speck"`
- `desc "Ultra-fast container runtime for Apple Silicon — VPN-proof networking"`
- `homepage "https://github.com/speck-vm/speck"`
- `depends_on macos: ">= :ventura"` — Virtualization.framework VZFileHandleNetworkDeviceAttachment and live resolver update features require macOS 13.0 (Ventura). Omitting this allows installation on Monterey (12.x) where spk up will silently fail at runtime.
- `pkg "spk-#{version}-#{arch}-apple-darwin.pkg"` — instructs Homebrew to run `installer -pkg` rather than extracting a binary and re-signing it. This is the critical stanza that preserves the Developer ID Application signature and stapled notarization ticket.
- `uninstall pkgutil: "io.speck.spk", delete: "/usr/local/bin/spk"` — two-key uninstall: `pkgutil:` removes the macOS installer receipt registered under the bundle identifier `io.speck.spk` (MUST match the `--identifier io.speck.spk` argument in the pkgbuild step in release.yml); `delete:` ensures the binary is removed even if pkgutil receipt removal leaves it behind.
- `zap trash: "~/.speck"` — removes the user home data directory on `brew uninstall --zap`.

Close the block with `end`.

Do not add a `test do` block — the Formula pattern used `assert_match "spk #{version}"` but Casks do not support the same test DSL structure and brew audit will flag it.

  <action>
Delete Formula/speck.rb using `git rm Formula/speck.rb`.

Rationale: A Homebrew tap cannot contain both a Formula named "speck" and a Cask named "spk" that installs the same binary — `brew` will error on install. Additionally, the Formula distributes a tar.gz that Homebrew re-signs with an ad-hoc certificate; the comment on line 12 of Formula/speck.rb ("Homebrew re-signs with --preserve-metadata=entitlements") is misleading — the entitlement technically survives but the Developer ID Application chain is broken and offline Gatekeeper verification fails. The Cask approach replaces this entirely.

Do not archive the file or move it to docs/. The Cask formula at Casks/spk.rb serves as the authoritative distribution descriptor going forward.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tap repo (speck-runtime/homebrew-speck) → Homebrew → user machines | Cask formula is the trust anchor: SHA256 pin + notarized .pkg |
| .pkg download URL → user machines | HTTPS download from GitHub Releases; SHA256 in Cask prevents substitution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-05 | Tampering | Casks/spk.rb sha256 field | mitigate | SHA256 computed by release CI post-staple and committed by update-cask.yml; any divergence between tap sha256 and actual .pkg causes `brew install` to abort with SHA-256 mismatch |
| T-14-06 | Spoofing | download URL in Casks/spk.rb | mitigate | URL points to signed GitHub release under HTTPS; SHA256 pin prevents binary substitution even if DNS is compromised |
| T-14-07 | Tampering | Formula/speck.rb deletion | accept | Deleting the Formula removes an incorrect distribution path that gave a false impression of entitlement preservation; no security regression |
| T-14-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan |
</threat_model>
