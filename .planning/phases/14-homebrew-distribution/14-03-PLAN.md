--- A. Apple Developer ID Installer Certificate ---

Developer ID Installer is a distinct cert type from Developer ID Application. Using the Application cert for package signing causes pkgbuild to fail with a cert-type mismatch (Pitfall 2 from RESEARCH.md). Provision steps:
1. Apple Developer Portal → Account → Certificates → + → Developer ID Installer → follow CSR flow → download .cer → import to Keychain Access.
2. In Keychain Access: right-click the "Developer ID Installer: ..." cert → Export → save as .p12 → set password.
3. Base64 encode: `base64 -i installer_cert.p12 | pbcopy`
4. Get identity string: `security find-identity -v -p basic` — copy the full "Developer ID Installer: ..." line.

--- B. GitHub Secrets in speck-vm/speck ---

github.com/speck-vm/speck → Settings → Secrets and variables → Actions → New repository secret.
Add four secrets:
- BUILD_INSTALLER_CERTIFICATE_BASE64  →  base64 output from A.3
- P12_INSTALLER_PASSWORD              →  password from A.2
- DEVELOPER_ID_INSTALLER_NAME         →  identity string from A.4
- TAP_REPO_TOKEN                      →  GitHub PAT from step C.5

--- C. Create the Homebrew Tap Repository ---

1. Create GitHub org speck-runtime at github.com/organizations/new (or confirm it exists).
2. Create repository named exactly homebrew-speck under speck-runtime (github.com/speck-runtime/homebrew-speck). Homebrew auto-resolves `brew tap speck-runtime/speck` to github.com/speck-runtime/homebrew-speck — the name must be exact.
3. In homebrew-speck, create directory Casks/ and commit Casks/spk.rb with the content from Casks/spk.rb in the main speck-vm/speck repo (produced by plan 14-02).
4. Create .github/workflows/update-cask.yml in homebrew-speck with the following YAML content (copy verbatim):

name: Update Cask

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version without v prefix (e.g. 0.1.0)'
        required: true
      sha256:
        description: 'SHA256 of the stapled .pkg file'
        required: true

jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
      - name: Update version and sha256 in Cask
        run: |
          sed -i "s/  version .*/  version \"${{ github.event.inputs.version }}\"/" Casks/spk.rb
          sed -i "s/  sha256 .*/  sha256 \"${{ github.event.inputs.sha256 }}\"/" Casks/spk.rb
      - name: Commit and push
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add Casks/spk.rb
          git commit -m "chore: update spk to v${{ github.event.inputs.version }}"
          git push

5. Create a GitHub PAT (classic) at github.com/settings/tokens/new with repo + workflow scopes scoped to speck-runtime/homebrew-speck. Add this token as TAP_REPO_TOKEN secret in speck-vm/speck (step B).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Apple Developer Portal → GitHub Secrets | .p12 private key material encoded and stored; must never touch the filesystem permanently |
| GitHub Secrets → CI environment | Secrets injected at runtime only; never logged or echoed |
| User machine → brew install | HTTPS download from GitHub Releases + SHA256 check + Gatekeeper notarization ticket verification |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-08 | Information Disclosure | Developer ID Installer .p12 key during provisioning | mitigate | Base64-encode on local machine; paste directly into GitHub Secrets UI; delete local .p12 after encoding; never commit to repo or log in terminal history |
| T-14-09 | Tampering | TAP_REPO_TOKEN scope | mitigate | PAT must have repo + workflow scope scoped to speck-runtime/homebrew-speck only — avoid org-wide write access; use fine-grained PAT if available |
| T-14-10 | Spoofing | update-cask.yml sed substitution | accept | sed replacements are version/sha256 strings computed by CI from the notarized .pkg; any tampering of the tap Cask after update is caught by `brew install`'s SHA256 check |
| T-14-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan |
</threat_model>
