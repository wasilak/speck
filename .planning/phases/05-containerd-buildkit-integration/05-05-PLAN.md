<action>
In `crates/speck-vz/src/guest.rs`:

1. Add `use std::path::PathBuf;` to the import block.

2. Add `pub fn wait_for_ready(&self) -> Result&lt;(), Error&gt;`:
   - Get `ready_vsock_port` from `self.config.ready_vsock_port.ok_or_else(|| Error::VsockConnect("ready_vsock_port not configured in GuestConfig".into()))?`
   - Delegate: `self.thread.wait_for_ready(ready_vsock_port)`

3. Add `pub fn containerd_unix_proxy(&self) -> Result&lt;PathBuf, Error&gt;`:
   - Get `containerd_vsock_port` from `self.config.containerd_vsock_port.ok_or_else(|| Error::VsockConnect("containerd_vsock_port not configured".into()))?`
   - Connect vsock: `let vsock = self.vsock_connect(containerd_vsock_port)?;`
   - Create temp Unix socket path: use `std::env::temp_dir().join(format!("speck-containerd-{}-{}.sock", std::process::id(), containerd_vsock_port))` — unique per process + port.
   - Create `std::os::unix::net::UnixListener::bind(&sock_path).map_err(Error::NetworkIo)?`
   - Spawn bridge thread: `std::thread::spawn(move || { if let Ok((stream, _)) = listener.accept() { bridge_vsock_unix(vsock, stream); } });`
   - Return `Ok(sock_path)`

4. Add private function `fn bridge_vsock_unix(vsock: VzSocket, stream: std::os::unix::net::UnixStream)`:
   - Dup the vsock fd using `libc::dup(vsock.as_raw_fd())` to get a second raw fd for the second direction. Wrap it in an `unsafe { VzSocket::from_raw_fd(dup_fd) }`.
   - Clone the UnixStream using `stream.try_clone().expect("clone unix stream")`.
   - Spawn one thread for vsock→unix direction:
     `let mut stream_write = stream_clone; let vsock_read = vsock;`
     Loop: `vsock_read.read(&mut buf)` → write all bytes to `stream_write` (use `std::io::Write::write_all`). Break on 0 bytes or error.
   - In current thread, handle unix→vsock direction:
     `let mut stream_read = stream; let vsock_write = vsock_dup;`
     Loop: `std::io::Read::read(&mut stream_read, &mut buf)` → `vsock_write.write(&buf[..n])` in a write loop. Break on 0 bytes or error.
   - Use `use std::io::{Read, Write};` inside the function scope.
   - Buffer size: 4096 bytes.

   Add `use std::os::unix::io::AsRawFd;` to the import block if not already present (needed for vsock.as_raw_fd()).

   Important: `VzSocket::from_raw_fd` is `pub(crate)`. This function is inside `crates/speck-vz`, so the call is valid.

   Important: The bridge function is infallible (errors just end the copy loop). Do NOT propagate errors via Result — the thread owns the fds and closes them on drop.

Do NOT import `containerd_client` in guest.rs — the library does not depend on it. Only the integration test (dev-dependency) uses it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guest gRPC → host Unix socket proxy | containerd_unix_proxy() creates a temp Unix socket on the host. Any process on the host that discovers the socket path can send gRPC to in-guest containerd. |
| bridge thread fd ownership | bridge_vsock_unix uses libc::dup() for raw fds. An fd leak in the bridge could leave dangling connections. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Spoofing | Temp Unix socket path (containerd_unix_proxy) | mitigate | Socket path includes PID + port for uniqueness. The socket is created in $TMPDIR which is user-private on macOS (scoped to the running user). Other users cannot reach it. |
| T-05-05-02 | Elevation of Privilege | containerd gRPC via Unix socket (no auth) | accept | Phase 5 is local dev tooling. The Unix socket is user-owned, ephemeral, and only exists while the proxy thread is running. Production-grade mTLS or namespace auth is tracked for Phase 9+. |
| T-05-05-03 | Denial of Service | bridge_vsock_unix fd leak if bridge panics | mitigate | VzSocket and UnixStream implement Drop that closes their fds. If bridge_vsock_unix panics, the thread exits and Drop runs, closing all fds. No fd leak on panic. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No new Cargo dependencies added in this plan. containerd-client was already added to dev-dependencies in Plan 05-04. |
</threat_model>
