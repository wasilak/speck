<objective>
Implement the guest-side vsock forwarder module and extend vminitd to supervise containerd + buildkitd.

Purpose: When the VM boots with the Phase 5 rootfs disk attached, vminitd (PID 1) must mount the disks, spawn and supervise the container runtime binaries, health-check containerd until it responds, signal the host (READY), then start forwarding containerd and buildkitd gRPC traffic over vsock. This plan implements that entire guest boot sequence. (D-01, D-03, D-04, D-05, D-06, D-07, D-09)

Output: `sock_forwarder.rs` (new module), `lib.rs` update (module registration), `vminitd.rs` (extended main + helpers). All cross-compiled to `aarch64-unknown-linux-musl`.
</objective>

<action>
Create `crates/speck-guest/src/sock_forwarder.rs` with `#![cfg(target_os = "linux")]` at the top.

The module provides a single public function:
  `pub fn serve(vsock_port: u32, unix_path: &'static str) -> io::Result<()>`

Behavior of `serve()`:
1. Create an AF_VSOCK SOCK_STREAM listening socket — use identical `sockaddr_vm` construction, bind, listen pattern from `dns_forwarder.rs` lines 27–53.
2. Loop indefinitely accepting connections: `libc::accept(listen_fd, ...)` — do NOT close the listen fd after first accept (this forwarder must handle reconnects, unlike dns_forwarder).
3. Per accepted vsock connection: call `unix_connect(unix_path)` to get a Unix socket fd. If unix_connect fails (ENOENT/ECONNREFUSED — socket not ready yet), close the vsock fd and continue the loop.
4. When both fds are open, spawn bidirectional copy using two threads:
   - Thread A: reads from vsock_fd, writes to unix_fd; on read returning 0 or error, shuts down and exits.
   - Thread B: reads from unix_fd, writes to vsock_fd; same termination condition.
   - Each thread closes its target fd on exit.
   - Use `libc::dup()` for each fd before spawning threads so each thread owns its fd pair independently.
5. Main loop re-accepts the next vsock connection after the prior pair is spawned (threads handle the lifecycle).

Add a private helper function:
  `fn unix_connect(path: &str) -> io::Result<libc::c_int>`

Behavior of `unix_connect()`:
1. Create AF_UNIX SOCK_STREAM socket via `libc::socket(libc::AF_UNIX, libc::SOCK_STREAM, 0)`.
2. Initialize `libc::sockaddr_un` with `std::mem::zeroed()`, set `sun_family = AF_UNIX as u16`, copy `path.as_bytes()` into `sun_path` as `i8` slice (use `std::mem::transmute` or cast — path must be shorter than 108 bytes).
3. Call `libc::connect()`. On failure: close fd, return Err(last_os_error()).
4. Return Ok(fd).

Do not use async, tokio, or any non-libc I/O in this file. All syscalls use libc directly. Match the style of dns_forwarder.rs exactly.

In `crates/speck-guest/src/lib.rs`, add `#[cfg(target_os = "linux")] pub mod sock_forwarder;` following the dns_forwarder declaration pattern.
</action>

Add a private function `fn mount_early_filesystems()` that calls libc::mount() for:
  1. procfs: source="proc", target="/proc", fstype="proc", flags=0
  2. sysfs: source="sysfs", target="/sys", fstype="sysfs", flags=0
  3. devtmpfs: source="devtmpfs", target="/dev", fstype="devtmpfs", flags=0

Add a private function `fn mount_disks()` that:
  1. Creates /rootfs with `std::fs::create_dir_all("/rootfs")` (ignore if exists).
  2. Mounts /dev/vda at /rootfs as ext4 (libc::mount, source="/dev/vda", target="/rootfs", fstype="ext4", flags=libc::MS_RELATIME, data=std::ptr::null()).
  3. Creates /rootfs/var/lib/containerd with `std::fs::create_dir_all` (ignore if exists).
  4. Mounts /dev/vdb at /rootfs/var/lib/containerd as ext4 (same libc::mount pattern).
  5. Creates /rootfs/run/ and /rootfs/tmp/ with create_dir_all (ignore if exists).
  On any mount failure: `eprintln!` and `std::process::exit(1)`.

Add a private function `fn wait_for_containerd_socket(max_attempts: u32) -> bool` that:
  Loops up to max_attempts (suggested: 50) times:
  1. Attempts `unix_connect_once("/rootfs/run/containerd/containerd.sock")` — a private helper that does AF_UNIX connect and immediately closes on success.
  2. If connect succeeds, return true.
  3. If ENOENT or ECONNREFUSED, sleep 200ms and retry.
  Returns false if all attempts exhausted.

Add a private helper `fn unix_connect_once(path: &str) -> bool` using libc::socket + libc::connect with sockaddr_un, returns true if connect succeeds (closes fd on success or failure).

Add a private function `fn send_ready_signal(ready_vsock_port: u32)`:
  1. Create AF_VSOCK SOCK_STREAM socket.
  2. Bind to ready_vsock_port on VMADDR_CID_ANY — same sockaddr_vm pattern as dns_forwarder.
  3. listen(fd, 1), accept one connection.
  4. Write b"READY\n" to the accepted fd.
  5. Close both fds. Non-fatal on error (eprintln + return).

Add a private function `fn spawn_service_with_restart(name: &'static str, program: &'static str, args: &'static [&'static str])` that:
  Spawns a `std::thread::spawn` closure that:
  1. Loops forever: `std::process::Command::new(program).args(args).spawn()` → `.wait()`.
  2. If spawn fails: eprintln + sleep 1s + retry.
  3. If process exits: eprintln with exit status, sleep 1s, restart (backoff D-06).

Rewrite `main()` to:
  1. Parse cmdline: `let port = parse_cmdline_vsock_port(...).unwrap_or(1234)` (existing, may be unused now but keep)
  2. Parse `dns_port = parse_cmdline_dns_port(...)` (existing)

Remove the call to `speck_guest::vsock_echo::serve(port)` from main — it was the old blocking call. The vsock echo module can remain in the codebase (for Phase 3 tests) but is no longer called from vminitd main().

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vsock→UnixSocket | Bytes from the host vsock connection are proxied to containerd.sock or buildkitd.sock inside the guest. Any host client that can reach vsock port 9001/9002 has full access to containerd/buildkitd gRPC. |
| vminitd→disk | vminitd reads device node paths (/dev/vda, /dev/vdb) passed as kernel cmdline constants — no user-controlled path injection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Spoofing | containerd.sock via vsock (port 9001) | accept | Phase 5 is a local dev tool running a single VM with a single owner. The vsock port is only accessible from the host (no network exposure). Production mTLS concern tracked for Phase 9+. |
| T-05-02-02 | Tampering | sock_forwarder unix_path argument | mitigate | `unix_path` is a `'static str` — passed as a compile-time constant from vminitd, not from user input or environment. No path injection possible. |
| T-05-02-03 | Denial of Service | vminitd restart loop | accept | Backoff delay is 1s; a crashing service will restart but not spin 100% CPU. Acceptable for Phase 5 dev tooling. |
| T-05-02-04 | Elevation of Privilege | containerd spawned with vminitd (PID 1) privileges | accept | containerd runs as PID 1's child inside the VM. The VM itself is the isolation boundary; containerd cannot reach the host filesystem. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | This plan adds no new Cargo dependencies (speck-guest already has libc). No new package fetches. |
</threat_model>
