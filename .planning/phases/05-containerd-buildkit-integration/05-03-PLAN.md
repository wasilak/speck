<action>
Create `scripts/fetch-rootfs.sh` with `#!/usr/bin/env bash` + `set -euo pipefail`.

Variables (following fetch-kernel.sh naming conventions):
  ROOTFS_VERSION="${1:-0.1.0}"
  SPECK_HOME="${SPECK_HOME:-$HOME/.local/share/speck}"
  ROOTFS_DEST="${SPECK_HOME}/rootfs"
  RELEASE_BASE="https://github.com/speck-vm/speck/releases/download"
  ROOTFS_IMG="${ROOTFS_DEST}/rootfs.img"
  ROOTFS_SUM="${ROOTFS_DEST}/rootfs.img.sha256"
  DATA_IMG="${ROOTFS_DEST}/data.img"

Step 1 — Skip if already present (idempotent):
  `if [ -f "${ROOTFS_IMG}" ]; then echo "==> rootfs image already present, skipping"; exit 0; fi`

Step 2 — Create directory:
  `mkdir -p "$ROOTFS_DEST"`

Step 3 — Download SHA256 checksum file first:
  `curl -fsSL "${RELEASE_BASE}/rootfs-${ROOTFS_VERSION}/speck-rootfs-${ROOTFS_VERSION}-arm64.img.sha256" -o "${ROOTFS_SUM}"`
  (If the release artifact doesn't exist yet during development, this will fail with a non-zero exit code, which is the correct behavior — don't add --silent that swallows errors.)

Step 4 — Download and decompress rootfs image:
  `curl -fsSL "${RELEASE_BASE}/rootfs-${ROOTFS_VERSION}/speck-rootfs-${ROOTFS_VERSION}-arm64.img.gz" | gunzip -c > "${ROOTFS_IMG}"`

Step 5 — Verify SHA256:
  ```
  EXPECTED=$(cat "${ROOTFS_SUM}" | awk '{print $1}')
  ACTUAL=$(shasum -a 256 "${ROOTFS_IMG}" | awk '{print $1}')
  if [ "${EXPECTED}" != "${ACTUAL}" ]; then
      echo "ERROR: SHA256 mismatch for rootfs.img"
      echo "  Expected: ${EXPECTED}"
      echo "  Actual:   ${ACTUAL}"
      rm -f "${ROOTFS_IMG}" "${ROOTFS_SUM}"
      exit 1
  fi
  ```

Step 6 — Create data disk stub (zero-filled 512 MB raw file) if not present:
  `if [ ! -f "${DATA_IMG}" ]; then dd if=/dev/zero of="${DATA_IMG}" bs=1M count=512 status=progress 2>&1 || true; fi`
  Note: vminitd will call `mke2fs -t ext4` on /dev/vdb on first boot if it detects no filesystem. The zero-filled file is a valid virtio-blk attachment that passes VZDiskImageStorageDeviceAttachment validation.

Step 7 — Done message following fetch-kernel.sh style:
  `echo "==> Done!"`
  `echo "    Rootfs: ${ROOTFS_IMG} ($(du -h "${ROOTFS_IMG}" | cut -f1))"`
  `echo "    Data disk stub: ${DATA_IMG} ($(du -h "${DATA_IMG}" | cut -f1))"`

Make the file executable: `chmod +x scripts/fetch-rootfs.sh`.

Use `shasum -a 256` (not `sha256sum`) because macOS ships `shasum`, not `sha256sum`. The CI runner uses Linux where `sha256sum` exists, but fetch-rootfs.sh must work on the developer's Mac.
</action>

Create `.github/workflows/build-rootfs.yml` following the CI build outline from RESEARCH.md. Key structure:

  name: Build speck rootfs image

  on:
    workflow_dispatch:
      inputs:
        version:
          description: Rootfs version (e.g. 0.1.0)
          required: true
          default: "0.1.0"
    push:
      tags: ["rootfs-v*"]

  jobs:
    build:
      runs-on: ubuntu-24.04-arm
      steps:
        - uses: actions/checkout@v4

        - name: Create raw ext4 image (512 MB)
          run: |
            dd if=/dev/zero of=rootfs.img bs=1M count=512
            mkfs.ext4 -O dir_index,extent -L speck-rootfs rootfs.img

        - name: Mount and populate rootfs
          run: |
            mkdir -p /tmp/rootfs
            sudo mount -o loop rootfs.img /tmp/rootfs
            sudo mkdir -p /tmp/rootfs/{usr/bin,usr/local/bin,etc/containerd,run,tmp,proc,sys,var/lib/containerd}

            # Install containerd 2.3.2 static arm64
            curl -fsSL https://github.com/containerd/containerd/releases/download/v2.3.2/containerd-static-2.3.2-linux-arm64.tar.gz \
              | sudo tar -C /tmp/rootfs/usr/local -xz

            # Install runc 1.5.0
            sudo curl -fsSL https://github.com/opencontainers/runc/releases/download/v1.5.0/runc.arm64 \
              -o /tmp/rootfs/usr/bin/runc
            sudo chmod +x /tmp/rootfs/usr/bin/runc

            # Install buildkitd 0.31.1
            curl -fsSL https://github.com/moby/buildkit/releases/download/v0.31.1/buildkit-v0.31.1.linux-arm64.tar.gz \
              | sudo tar -C /tmp/rootfs/usr/local -xz

            # Write containerd config.toml (version 3, overlayfs snapshotter)
            sudo tee /tmp/rootfs/etc/containerd/config.toml &lt;&lt;'EOF'
            version = 3
            [plugins.'io.containerd.cri.v1.images']
              snapshotter = "overlayfs"
            EOF

            sudo umount /tmp/rootfs

        - name: Compress and compute checksum
          run: |
            gzip -9 -c rootfs.img > speck-rootfs-${{ github.event.inputs.version || github.ref_name }}-arm64.img.gz
            shasum -a 256 rootfs.img > speck-rootfs-${{ github.event.inputs.version || github.ref_name }}-arm64.img.sha256

        - name: Upload as GitHub Release artifact
          uses: softprops/action-gh-release@v2
          with:
            tag_name: rootfs-${{ github.event.inputs.version || github.ref_name }}
            files: |
              speck-rootfs-*.img.gz
              speck-rootfs-*.img.sha256

The YAML must be syntactically valid. Use 2-space indentation throughout.

Note on containerd config.toml: Write `version = 3` (containerd 2.x format, per RESEARCH.md §State of the Art). The `[plugins.'io.containerd.cri.v1.images']` stanza sets `snapshotter = "overlayfs"`. If overlayfs is unavailable on the kernel, vminitd can be extended to write `snapshotter = "native"` as a fallback — this is NOT in scope for Phase 5.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet→host filesystem | fetch-rootfs.sh downloads a binary disk image from GitHub Releases. A tampered image would contain malicious binaries run as PID 2+ inside the VM. |
| GitHub Actions→release | build-rootfs.yml creates and uploads the artifact. The release upload uses the GITHUB_TOKEN (scoped to the repo); no external secrets needed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Tampering | rootfs.img download (fetch-rootfs.sh) | mitigate | SHA256 checksum downloaded separately and verified before rootfs.img is used. On mismatch: delete image and exit 1. (Per RESEARCH.md §Security — SHA256 checksum verification) |
| T-05-03-02 | Information Disclosure | stale rootfs with CVE-bearing containerd/runc/buildkitd | mitigate | Version pins in both fetch-rootfs.sh (ROOTFS_VERSION arg) and build-rootfs.yml (explicit download URLs). Developer re-runs `cargo xtask init` with new version to upgrade. |
| T-05-03-03 | Denial of Service | zero-filled data.img as VZDiskImageStorageDeviceAttachment | accept | A zero-filled raw file is a valid attachment; VZDiskImageStorageDeviceAttachment accepts RAW format. vminitd checks for ext4 signature on first mount and formats if absent. Low severity. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | This plan adds no new Cargo dependencies. xtask and scripts changes are pure Rust + bash. No new package fetches. |
</threat_model>
