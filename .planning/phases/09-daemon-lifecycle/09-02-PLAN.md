<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon → control socket | Accepts any local connection; ping-pong only, no command parsing |
| daemonize() → filesystem | Writes plist to ~/Library/LaunchAgents/; plist contains binary path from std::env::current_exe() |
| shutdown_gracefully() → Docker socket | HTTP GET to local speck.sock; parses JSON array of containers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-06 | Tampering | control.sock (accept loop) | mitigate | Bound with 0o600 permissions (owner-only) immediately after bind; no command channel — only writes PONG\n back; accepts any connection without parsing input |
| T-09-07 | Elevation of Privilege | plist write to ~/Library/LaunchAgents | accept | Path is computed from HOME + fixed LAUNCHD_LABEL; binary path is from std::env::current_exe() (not user input); plist is written atomically via std::fs::write |
| T-09-08 | Information Disclosure | daemon logs in speck.log | mitigate | tracing events in run_up and shutdown_gracefully must log only lifecycle info (container IDs, counts, errors); never log Docker API response bodies in full or user environment variables |
| T-09-09 | Denial of Service | KeepAlive restart storm | accept | launchd has built-in throttling; startup errors are logged before exit so cause is traceable; RunAtLoad=false prevents auto-start on login |
| T-09-10 | Tampering | shutdown_gracefully → /containers/{id}/stop | accept | Container ID comes from GET /containers/json response on the local trusted socket; no external user input is interpolated into the stop URL |
</threat_model>
