    in the package legitimacy audit because slopcheck was unavailable at research time. Per the

    Packages to verify (all on crates.io):
    1. system-configuration 0.7.0 — https://crates.io/crates/system-configuration
       Expected: Maintained by Mullvad (github.com/mullvad/system-configuration-rs), 6+ year history,
       high download count, actively maintained. Provides high-level SCDynamicStore API.

    2. system-configuration-sys 0.6.0 — https://crates.io/crates/system-configuration-sys
       Expected: Same repository as above (mullvad/system-configuration-rs), FFI layer only.
       Required for SCDynamicStoreSetDispatchQueue (not in high-level crate).

    3. core-foundation 0.10.1 — https://crates.io/crates/core-foundation
       Expected: Maintained by Mozilla/Servo project (github.com/servo/core-foundation-rs),
       9+ year history, very high download count (used by Firefox, many macOS crates).
       Provides CFString, CFArray, CFDictionary for SCDynamicStore values.

    4. dispatch2 0.3.1 — https://crates.io/crates/dispatch2
       Expected: Part of the objc2 ecosystem (github.com/madsmtm/objc2), already present in
       Cargo.lock as a transitive dependency via objc2-vz. Adding as explicit direct dep.
  </what-built>
  <how-to-verify>

    - Source repository matches the expected repo (not a fork, not an unknown author)
    - Download counts are non-trivial (at minimum thousands of downloads)
    - Recent publication date consistent with active maintenance

    For dispatch2: also run `cargo tree -p speck-net | grep dispatch2` to confirm it is already
    present transitively (confirming it is a safe explicit addition).
