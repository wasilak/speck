## v1.1 Requirements

Milestone v1.1: Production Runtime. Scope: make `spk` a real daily-driver container runtime — close v1.0 gaps, add daemon lifecycle, VPN-proof DNS, corporate cert injection, config file, VM resource controls, shell integration, diagnostics, and Homebrew distribution.

REQ-ID format: `CATEGORY-NN`.

---

### Gap Closure — v1.0 Completion (GAP)

- [x] **GAP-01**: Phase 06.1 is fully complete — `spawn_blocking` fix wired, VM delegate drain thread active, all missing objc2-vz feature flags present
- [x] **GAP-02**: User-space netstack (`SpeckNet::spawn()`) is called in the production `run_up` path — containers have working network egress
- [x] **GAP-03**: CLI `DockerClient` connects via Unix socket (not TCP) — `spk run`, `spk ps`, `spk exec`, `spk stop` all work end-to-end
- [x] **GAP-04**: Port bindings (`-p host:container`) are applied at container start via `guest.add_port_map()` — published ports are reachable on macOS localhost

### Daemon Lifecycle (DAEMON)

- [x] **DAEMON-01**: `spk up` starts the runtime as a background process by default using a launchd LaunchAgent re-exec pattern (no `fork()`)
- [x] **DAEMON-02**: `spk up --foreground` runs inline with all logs streamed to stdout/stderr (for CI and debugging)
- [x] **DAEMON-03**: `spk down` stops the daemon and VM cleanly, removing the LaunchAgent
- [x] **DAEMON-04**: `spk restart` — implemented as `spk down && spk up`; first-class `spk restart` subcommand deferred per Phase 09 CONTEXT.md §Deferred
- [x] **DAEMON-05**: Daemon logs are written to `$SPECK_HOME/speck.log`; liveness is detected via control socket (`$SPECK_HOME/run/control.sock`), not a PID file

### Shell Environment Integration (SHELL)

- [x] **SHELL-01**: `spk env` prints shell-ready export statements for `DOCKER_HOST` and `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE`
- [x] **SHELL-02**: `spk init` writes a guarded block (`# BEGIN speck` / `# END speck`) to `~/.zshrc`, `~/.bashrc`, or fish config — idempotent across multiple invocations
- [x] **SHELL-03**: `spk init` is opt-in for setting `DOCKER_HOST` and warns if another runtime's `DOCKER_HOST` is already active

### VM Resource Configuration (VMCFG)

- [x] **VMCFG-01**: User can set vCPU count via `--cpus` CLI flag or `vm.cpus` in config — validated against host physical core count
- [x] **VMCFG-02**: User can set RAM size via `--memory` CLI flag or `vm.memory_mb` in config — validated ≥ 512 MiB
- [x] **VMCFG-03**: User can set data disk size via `--disk` CLI flag or `vm.disk_gb` in config — disk can grow, shrink is an explicit error
- [x] **VMCFG-04**: Resource changes that require a VM restart are announced by `spk up` with a clear message; no silent no-op

### Config File (CFG)

- [x] **CFG-01**: Speck reads `$SPECK_HOME/config.yaml` on startup with precedence: env var > CLI flag > config file > built-in default
- [x] **CFG-02**: Config schema is versioned (`version: 1`); unknown keys produce a warning, not a panic; `serde(deny_unknown_fields)` in strict mode
- [x] **CFG-03**: Environment variables `SPECK_VM_CPUS`, `SPECK_VM_MEMORY_MB`, `SPECK_VM_DISK_GB`, `SPECK_LOG_LEVEL` override their config file equivalents

### VPN-Proof DNS (DNS)

- [x] **DNS-01**: Host never binds any port on `:53` for DNS — the DNS proxy runs inside the VM network namespace only (architectural: no bind(53) in speck-net; manual lsof verify deferred to v1.2)
- [x] **DNS-02**: Guest DNS queries are forwarded over vsock to a host-side handler that resolves via the live macOS system resolver (SCDynamicStore / `getaddrinfo`)
- [x] **DNS-03**: Container DNS works while Cloudflare WARP is active — WARP resolvers at `127.0.2.2` and `127.0.2.3` are reachable from the host DNS handler (architectural guarantee; live verify deferred to v1.2)
- [x] **DNS-04**: Split DNS: queries for VPN-scoped domains route to VPN resolvers; all other queries route to the default system resolver
- [x] **DNS-05**: DNS resolver configuration updates live when macOS network configuration changes (VPN toggle, Wi-Fi handoff) — no VM restart required (architectural: SCDynamicStoreSetDispatchQueue; live verify deferred to v1.2)
- [x] **DNS-06**: NXDOMAIN responses from VPN-scoped resolvers are translated to SERVFAIL so DNS clients retry after VPN reconnects

### Corporate Certificate Injection (CERT)

- [x] **CERT-01**: User can specify custom CA certificate paths in `config.yaml` under `ca.extra_certs`
- [x] **CERT-02**: Specified CA certificates are injected into the guest OS trust bundle (`update-ca-certificates`) before containerd and buildkitd start
- [x] **CERT-03**: Specified CA certificates are configured in containerd `hosts.toml` and buildkitd `config.toml` registry trust sections
- [x] **CERT-04**: `spk up` fails fast with a clear error message if a configured certificate file is missing or is not valid PEM

### Diagnostics (DOCTOR)

- [x] **DOCTOR-01**: `spk doctor` runs a health check suite and exits 0 only when all checks pass, exits 1 on any FAIL (verified 2026-07-06)
- [x] **DOCTOR-02**: Health checks cover: binary codesign entitlement, VM running state, Docker socket reachability, `DOCKER_HOST` accuracy, public DNS resolution, VPN-scoped DNS resolution, cert injection status, and VM resource utilization (verified 2026-07-06)
- [x] **DOCTOR-03**: `spk doctor dns <hostname>` tests resolution of a specific hostname through the host vsock proxy DNS path and reports which resolver answered (verified 2026-07-06)

### Homebrew Distribution (BREW)

- [x] **BREW-01**: `brew install speck-runtime/speck/spk` installs a working `spk` binary with the `com.apple.security.virtualization` entitlement preserved (ad-hoc path via Formula + `--preserve-metadata=entitlements`; Developer ID Cask path deferred)
- [x] **BREW-02**: The release pipeline produces a signed artifact that survives Homebrew's re-signing step without losing the virtualization entitlement (ad-hoc signed tarball; notarized `.pkg` path deferred)
- [x] **BREW-03**: `brew upgrade spk` applies correctly without losing the entitlement or requiring manual re-signing (inherited from Formula ad-hoc re-sign path)

## Deferred to v1.2+

- **NETSTACK-V2**: Replace smoltcp/gvisor-tap-vsock with a fully native Rust netstack for sub-ms packet overhead
- **GUI-V2**: SwiftUI native app consuming speck-core
- **K8S-V2**: K3s injection via in-guest containerd/CRI seam
- **COMPOSE-V2**: First-class Compose ergonomics beyond raw Docker-API compatibility
- **CERT-V2**: Automatic CA detection from macOS Keychain (no explicit `ca.extra_certs` config needed)
- **DISK-RESIZE-V2**: Online disk grow with automated `growpart + resize2fs` in the guest
- **DNS-LIVE-VERIFY**: Live lsof/WARP/VPN toggle verification of DNS-01, DNS-03, DNS-05 (deferred — requires company machine + VPN)
- **BREW-DEVID**: Developer ID Installer + `.pkg` + notarytool + Cask distribution path (deferred — requires Apple Developer Program enrollment)
- **DAEMON-RESTART**: First-class `spk restart` subcommand (deferred — implemented as `spk down && spk up`)

## Out of Scope (v1.1)

- **Intel / x86_64 support** — Apple Silicon only, zero legacy debt
- **Host `:53` DNS binding** — architectural constraint D-09, never
- **double-fork / `daemonize` crate** — UB after Apple framework init, never
- **`VZNATNetworkDeviceAttachment`** — breaks WARP, decision D-02 is permanent
- **`com.apple.vm.networking` bridged networking** — Apple-gated entitlement, not on the critical path
- **Per-container CA injection post-start** — breaks image integrity; document tool-level env vars instead
- **Synthetic subnets** — NET-06 constraint, never
